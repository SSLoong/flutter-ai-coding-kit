# 提示词：实现并修复 Pigeon 通道

**用途**：在 Android/iOS 实现 HostApi、接入 FlutterApi，或根据生成/编译/运行报错修复

---

## 📋 适用场景

- 生成已经成功，需要写 Kotlin / Swift 实现并注册到 Engine
- 宿主要回调 Dart，需要接上生成的 FlutterApi
- `dart run pigeon`、`compileDebugKotlin`、`flutter build ios` 或真机 `PlatformException` 失败
- 多 Engine / add-to-app 下注册到了错误的 messenger

---

## 📥 输入要求

在 Cursor 中打开：

1. **定义文件**（如 `pigeons/battery_api.dart`）
2. **本次生成物**里对应的接口签名（Dart、Kotlin、Swift 各贴类声明，不要贴整个编解码）
3. **现有注册点**：`MainActivity.configureFlutterEngine`、`AppDelegate.didInitializeImplicitFlutterEngine`，或插件的 `onAttachedToEngine` / `register(with:)`
4. **失败时的完整报错**（生成器输出、Kotlin/Swift 编译错误，或 `PlatformException` / `MissingPluginException`）
5. **pigeon 版本**：`flutter pub deps | grep pigeon` 或 `pubspec.lock` 里的版本

## 💬 提示词模板

````markdown
根据已经生成的 Pigeon 接口，完成宿主实现，或修复我贴出的报错。

**定义文件**：`pigeons/[api_name].dart`

**生成签名**（以这些为准；若与定义文件的 Dart 类型字面不一致，以生成文件为准）：

Kotlin：
```kotlin
[粘贴 interface、数据类、枚举、FlutterError、setUp 签名]
```

Swift：
```swift
[粘贴 protocol、数据类、枚举、PigeonError、Setup.setUp 签名]
```

Dart：
```dart
[粘贴 HostApi 类声明与 FlutterApi 抽象类、setUp 签名]
```

**注册位置**：
- Android：[MainActivity.configureFlutterEngine 或 FlutterPlugin.onAttachedToEngine]
- iOS：[didInitializeImplicitFlutterEngine 或 FlutterPlugin.register]
- 是否 add-to-app / 多 Engine：[是或否]
- messageChannelSuffix：[空，或具体后缀]

**报错**（没有就写「无，请实现」）：
```
[粘贴完整错误，不要截断]
```

**实现要求**：

1. 只改宿主实现和 Dart 包装/注册。生成文件标记为 Autogenerated 的，不要直接改；需要改签名时回到 `pigeons/[api_name].dart` 并给出 `dart run pigeon --input pigeons/[api_name].dart`。
2. Kotlin：
   - Dart `int` 用 `Long`
   - 枚举用生成后的大写常量
   - 同步方法与 `@async` 方法抛 `FlutterError(code, message, details)`，`details` 必须是 StandardMessageCodec 支持的类型
   - 在目标 Engine 的 `binaryMessenger` 上调用 `setUp`；卸掉时 `setUp(messenger, null)`
3. Swift：
   - Dart `int` 用 `Int64`
   - 业务错误抛 `PigeonError(code:message:details:)`，不要抛 `FlutterError`
   - 应用模板使用 `didInitializeImplicitFlutterEngine`，messenger 用 `engineBridge.applicationRegistrar.messenger()`
   - 插件使用 `registrar.messenger()`
   - 调用 async FlutterApi 时留在 main actor（生成方法带 `@MainActor`）
4. Dart：
   - `WidgetsFlutterBinding.ensureInitialized()` 之后 `[FlutterApi].setUp(实现)`
   - 退出或 Engine 销毁时 `setUp(null)`
   - 业务代码通过构造函数接收生成的 HostApi，以便测试注入 fake / mock
   - 不要添加 `dartHostTestHandler`
5. 线程：
   - 无注解的 HostApi 跑在平台主线程，实现必须立刻返回
   - `@async` 是 `suspend` / `async throws`，Kotlin 侧由生成代码在 `Dispatchers.Main` 上启动
   - `@TaskQueue(serialBackgroundThread)` 的实现不要碰 UI，也不要在该线程直接调用 FlutterApi
6. 多 Engine：每个 `FlutterEngine` 用自己的 messenger 注册一次。`messageChannelSuffix` 只区分同一 messenger 上的多个实例，两侧字符串必须相同。
7. 输出完整可编译文件（含 package 与 import），并列出我要跑的验证命令。

若报错来自 Native Interop（`useJni` / `useFfi`、`jnigen`、`getInstance(name)`），先停下来说明：本文默认路径是平台通道；pigeon 30 的 `getInstance(name)` 已删除。不要在平台通道实现里混用这套 API。
````

## ✅ 验证步骤

修复或实现后执行：

```bash
dart run pigeon --input pigeons/[api_name].dart
dart analyze lib/src/[api_name].g.dart lib/[client_file].dart
flutter test test/[client_file]_test.dart
flutter build apk --debug
flutter build ios --no-codesign --debug
```

**检查清单**：

- [ ] 生成命令成功，且没有手改 `*.g.dart` / `*.g.kt` / `*.g.swift`
- [ ] Kotlin 实现的方法签名与生成的 `interface` 完全一致（含 `Long`、`suspend`）
- [ ] Swift 实现的方法签名与生成的 `protocol` 完全一致（含 `Int64`、`async throws`）
- [ ] Android、iOS 都对当前 Engine 的 messenger 调用了 `setUp`
- [ ] Dart 测试用 fake（继承生成 HostApi 并覆盖方法）或 mocktail `implements` 生成 HostApi，不依赖真机
- [ ] 真机失败路径能收到约定的 `PlatformException.code`，而不是 `channel-error` 或 `null-error`

## 🛠️ 常见问题

1. **生成器报错：方法体、不支持的类型、增强枚举**
   - 改定义文件，不要改生成物。`DateTime` 改成 `int` 毫秒；增强枚举改成简单枚举加数据类。

2. **Kotlin：`Type mismatch: inferred type is Int but Long was expected`，或运行期 Long/Int ClassCastException**
   - 生成接口的整数参数和返回值用 `Long`。枚举常量用 `BATTERY` 这种生成后的名字。

3. **Kotlin：`Unresolved reference 'kotlinx'`**
   - 只有 `@async` 的生成物会引用 `kotlinx.coroutines`。给 `android/app` 加上与当前 Kotlin 匹配的 `kotlinx-coroutines-android`，或去掉不需要挂起的 `@async` 后重新生成。

4. **Swift：`Int` 无法传给 `Int64`，或 `FlutterError` 不能 `throw`**
   - 数值转 `Int64`。错误类型用生成的 `PigeonError`。`@async` 方法保持 `async throws`，不要改回 completion，除非定义里写的是 `@asyncCallback` 并且生成签名确实是回调。

5. **Swift：`BatteryApi.g.swift` 找不到符号**
   - 文件不在 Runner target 里。同步目录的新工程确认文件在 `ios/Runner/` 下；旧工程在 Xcode 把该文件加进 Runner target。

6. **运行期 `channel-error` / `MissingPluginException`**
   - 宿主没 `setUp`，或 iOS 仍注册在 `didFinishLaunchingWithOptions`。UIScene 模板改到 `didInitializeImplicitFlutterEngine`。后缀不一致时，两侧同时改或同时留空。

7. **运行期 `null-error`**
   - 非空返回值在某一侧成了 null。把定义改成可空并重新生成三端，或在宿主保证非空并在失败时抛 `FlutterError` / `PigeonError`。

8. **Dart 单元测试 MissingPluginException**
   - 测试调用了生成类的真实方法。让业务类接收 `BatteryHostApi`，测试传入子类 fake 或 `Mock implements` 生成类，并覆盖被调用的方法。不要启用 `dartHostTestHandler`。

9. **add-to-app 串台**
   - 禁止缓存第一个 Engine 的 messenger 给后续 Engine 用。每个 Engine：宿主 `setUp` 一次，Dart entrypoint `FlutterApi.setUp` 一次，销毁时两侧都卸掉。

10. **只改了一端生成物**
    - 删掉三端生成文件后重新执行一次 `dart run pigeon`。不要手工对齐编解码。
